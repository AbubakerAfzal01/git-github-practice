# Day 12 - Issues + README + Professional Repository

## What I Learned
- What GitHub Issues are used for (tracking bugs, tasks, ideas)
- The full lifecycle of an Issue: open, comment, close
- What sections make a README professional
- My own root README already follows most professional standards

## What I Practiced
- Created a real GitHub Issue (#1) with a title and description
- Added a closing comment and closed the issue as completed
- Reviewed my root README against a professional structure checklist

## Key Takeaway
Issues are for tracking work, not just reporting bugs - I used one to track a real documentation task. A professional README isn't about following a strict template, but covering the key sections a visitor needs: what this is, what's in it, and how it's organized.
