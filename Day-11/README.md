# Day 11 - GitHub Branches & Pull Requests

## What I Learned
- What a Pull Request is and how it differs from git merge
- The full PR workflow: fork, branch, commit, create PR, review diff
- Only the repository owner (or authorized collaborators) can merge a PR
- When NOT to merge a PR - practiced good judgment on someone else's public repo

## What I Practiced
- Created a fork and a patch-1 branch on a public repository
- Created a real Pull Request and reviewed its diff and "able to merge" status
- Closed the PR responsibly instead of merging into a repo I didn't own

## Key Takeaway
A Pull Request is a request, not an action - only the repository owner decides whether to merge it. Creating a PR on someone else's project without a real reason to contribute isn't appropriate, even if GitHub allows it technically.
